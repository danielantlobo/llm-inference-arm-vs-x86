1. Memory Footprint: Transformer models require a large amount of memory for storing the weights and intermediate activations. When running on CPU, the main challenge is the memory footprint. As the number of parameters (i.e., the size of the model) grows, the memory requirements also increase. When running a CPU-only model, it is common to see a memory bottleneck when dealing with very large models. 2. Repeated Loading of Weights: As the number of parameters grows, so does the number of parameters that are loaded into the CPU. As the model grows in size, the loading of the weights from the CPU to the GPU can become a bottleneck. This is particularly true when the model is being used for inference where the model’s parameters are often reused. Quantisation can help address this challenge. When quantised, the model's parameters are represented by a set of binary values. These values can be read off the CPU and passed to the GPU for inference. When the model is running on a CPU-only system, the CPU can load the quantised values directly from the CPU into the GPU memory, reducing the number of memory accesses required for inference.
